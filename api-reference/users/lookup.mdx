## Overview

The user lookup endpoints let you fetch X user objects by numeric ID or username. You can look up a single user, batch up to 100 users in one request, or retrieve your own authenticated user profile. Use `user.fields` to specify exactly which fields you need and `expansions` to pull in related objects.

**Base URL:** `https://api.twitter.com`

**Authentication:** Bearer Token (app-only) for public user data. OAuth 2.0 with `users.read` scope for the `/me` endpoint.

---

## Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/2/users/:id` | Look up a single user by numeric ID |
| `GET` | `/2/users` | Batch look up up to 100 users by IDs |
| `GET` | `/2/users/by/username/:username` | Look up a single user by username |
| `GET` | `/2/users/by` | Batch look up up to 100 users by usernames |
| `GET` | `/2/users/me` | Look up the authenticated user |

## GET /2/users/:id

Returns a single user object for the given numeric user ID.

### Path Parameters

<ParamField path="id" type="string" required>
  The numeric ID of the user to look up. For example, `2244994945`.
</ParamField>

### Query Parameters

<ParamField query="user.fields" type="string">
  Comma-separated list of user fields to include in the response. Supported values:

  `id`, `name`, `username`, `created_at`, `description`, `entities`, `location`,
  `pinned_tweet_id`, `profile_image_url`, `protected`, `public_metrics`, `url`,
  `verified`, `verified_type`
</ParamField>

<ParamField query="expansions" type="string">
  Expand related objects inline. Supported value: `pinned_tweet_id` — includes the user's pinned Tweet as a full Tweet object in the `includes` section.
</ParamField>

<ParamField query="tweet.fields" type="string">
  Comma-separated list of Tweet fields to return when `pinned_tweet_id` is expanded. For example: `created_at,text,public_metrics`.
</ParamField>

### Example Request

<CodeGroup>
```bash cURL
curl -X GET "https://api.twitter.com/2/users/2244994945?user.fields=name,username,description,public_metrics,profile_image_url,verified,created_at" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```

```python Python
import requests

bearer_token = "YOUR_BEARER_TOKEN"
user_id = "2244994945"

url = f"https://api.twitter.com/2/users/{user_id}"
params = {
    "user.fields": "name,username,description,public_metrics,profile_image_url,verified,created_at"
}
headers = {"Authorization": f"Bearer {bearer_token}"}

response = requests.get(url, params=params, headers=headers)
print(response.json())
```

```javascript Node.js
const axios = require("axios");

const bearerToken = "YOUR_BEARER_TOKEN";
const userId = "2244994945";

axios
  .get(`https://api.twitter.com/2/users/${userId}`, {
    params: {
      "user.fields":
        "name,username,description,public_metrics,profile_image_url,verified,created_at",
    },
    headers: { Authorization: `Bearer ${bearerToken}` },
  })
  .then((res) => console.log(res.data))
  .catch((err) => console.error(err));
```
</CodeGroup>

## GET /2/users

Batch look up up to 100 users in a single request by providing a comma-separated list of numeric user IDs.

### Query Parameters

<ParamField query="ids" type="string" required>
  Comma-separated list of user IDs to look up. You can specify up to 100 IDs per request. Example: `2244994945,783214,6253282`.
</ParamField>

<ParamField query="user.fields" type="string">
  Comma-separated list of user fields to return. Supported values: `id`, `name`, `username`, `created_at`, `description`, `entities`, `location`, `pinned_tweet_id`, `profile_image_url`, `protected`, `public_metrics`, `url`, `verified`, `verified_type`.
</ParamField>

<ParamField query="expansions" type="string">
  Supported value: `pinned_tweet_id`.
</ParamField>

<ParamField query="tweet.fields" type="string">
  Tweet fields to include when expanding `pinned_tweet_id`.
</ParamField>

### Example Request

<CodeGroup>
```bash cURL
curl -X GET "https://api.twitter.com/2/users?ids=2244994945,783214,6253282&user.fields=name,username,public_metrics" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```
</CodeGroup>

## GET /2/users/by/username/:username

Returns a single user object for the given username (handle), without the leading `@`.

### Path Parameters

<ParamField path="username" type="string" required>
  The X username (handle) of the user, without the `@` symbol. Example: `XDevelopers`.
</ParamField>

### Query Parameters

<ParamField query="user.fields" type="string">
  Comma-separated list of user fields to return. Supported values: `id`, `name`, `username`, `created_at`, `description`, `entities`, `location`, `pinned_tweet_id`, `profile_image_url`, `protected`, `public_metrics`, `url`, `verified`, `verified_type`.
</ParamField>

<ParamField query="expansions" type="string">
  Supported value: `pinned_tweet_id`.
</ParamField>

<ParamField query="tweet.fields" type="string">
  Tweet fields to include when expanding `pinned_tweet_id`.
</ParamField>

### Example Request

<CodeGroup>
```bash cURL
curl -X GET "https://api.twitter.com/2/users/by/username/XDevelopers?user.fields=name,username,description,public_metrics,profile_image_url,verified,created_at" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```

```python Python
import requests

bearer_token = "YOUR_BEARER_TOKEN"
username = "XDevelopers"

url = f"https://api.twitter.com/2/users/by/username/{username}"
params = {
    "user.fields": "name,username,description,public_metrics,profile_image_url,verified,created_at"
}
headers = {"Authorization": f"Bearer {bearer_token}"}

response = requests.get(url, params=params, headers=headers)
print(response.json())
```
</CodeGroup>

## GET /2/users/by

Batch look up up to 100 users by usernames in a single request.

### Query Parameters

<ParamField query="usernames" type="string" required>
  Comma-separated list of usernames to look up. You can specify up to 100 usernames per request. Do not include the `@` prefix. Example: `XDevelopers,X,TwitterAPI`.
</ParamField>

<ParamField query="user.fields" type="string">
  Comma-separated list of user fields to return.
</ParamField>

<ParamField query="expansions" type="string">
  Supported value: `pinned_tweet_id`.
</ParamField>

<ParamField query="tweet.fields" type="string">
  Tweet fields to include when expanding `pinned_tweet_id`.
</ParamField>

### Example Request

<CodeGroup>
```bash cURL
curl -X GET "https://api.twitter.com/2/users/by?usernames=XDevelopers,X,TwitterAPI&user.fields=name,username,public_metrics" \
  -H "Authorization: Bearer $BEARER_TOKEN"
```
</CodeGroup>

## GET /2/users/me

Returns the user object for the currently authenticated user. This endpoint requires OAuth 2.0 user context authentication.

<Note>
  **Authentication required:** This endpoint uses OAuth 2.0 with the `users.read` scope. Bearer Token (app-only) is not supported.
</Note>

### Query Parameters

<ParamField query="user.fields" type="string">
  Comma-separated list of user fields to return. Supported values: `id`, `name`, `username`, `created_at`, `description`, `entities`, `location`, `pinned_tweet_id`, `profile_image_url`, `protected`, `public_metrics`, `url`, `verified`, `verified_type`.
</ParamField>

<ParamField query="expansions" type="string">
  Supported value: `pinned_tweet_id`.
</ParamField>

<ParamField query="tweet.fields" type="string">
  Tweet fields to include when expanding `pinned_tweet_id`.
</ParamField>

### Example Request

<CodeGroup>
```bash cURL
curl -X GET "https://api.twitter.com/2/users/me?user.fields=name,username,description,public_metrics" \
  -H "Authorization: Bearer $OAUTH2_USER_TOKEN"
```
</CodeGroup>

## Response Fields

<ResponseField name="id" type="string">
  The unique numeric identifier of the user.
</ResponseField>

<ResponseField name="name" type="string">
  The display name of the user, as set on their profile.
</ResponseField>

<ResponseField name="username" type="string">
  The X handle (screen name) of the user, without the leading `@`.
</ResponseField>

<ResponseField name="created_at" type="string (ISO 8601)">
  The UTC datetime when the user account was created.
</ResponseField>

<ResponseField name="description" type="string">
  The text of the user's profile bio.
</ResponseField>

<ResponseField name="public_metrics" type="object">
  Public engagement metrics for the user account.

  <Expandable title="public_metrics fields">
    <ResponseField name="followers_count" type="integer">
      Number of users following this account.
    </ResponseField>
    <ResponseField name="following_count" type="integer">
      Number of accounts this user follows.
    </ResponseField>
    <ResponseField name="tweet_count" type="integer">
      Total number of Tweets (including retweets) posted by this user.
    </ResponseField>
    <ResponseField name="listed_count" type="integer">
      Number of public Lists that include this user.
    </ResponseField>
    <ResponseField name="like_count" type="integer">
      Number of Tweets this user has liked.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="verified" type="boolean">
  Indicates whether the user has a legacy verified badge.
</ResponseField>

<ResponseField name="verified_type" type="string">
  The type of verification badge on the user's account. Possible values: `blue`, `business`, `government`, `none`.
</ResponseField>

<ResponseField name="profile_image_url" type="string">
  The HTTPS URL pointing to the user's profile image.
</ResponseField>

<ResponseField name="pinned_tweet_id" type="string">
  The ID of the user's pinned Tweet, if one exists. Expand with `expansions=pinned_tweet_id` to retrieve the full Tweet object.
</ResponseField>

<ResponseField name="protected" type="boolean">
  When `true`, the user's Tweets are only visible to their approved followers.
</ResponseField>

<ResponseField name="location" type="string">
  The location specified in the user's profile. This is a free-form string and may not be a real location.
</ResponseField>

<ResponseField name="url" type="string">
  The URL specified in the user's profile, in t.co shortened form.
</ResponseField>
