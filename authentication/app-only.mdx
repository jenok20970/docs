App-Only authentication lets your application call the X API using a single **Bearer Token** that represents your app rather than any individual user. There is no authorization flow, no callback URL, and no user interaction required — you simply attach the token to every request and you're ready to go.

This method grants your app access to **public, read-only data** at the application level. It is the fastest path to getting data from X, and it is ideal for server-side services, data pipelines, search tools, and any use case where you don't need to act on behalf of a specific user.

## Limitations

Before choosing App-Only authentication, make sure it covers your use case. App-Only tokens operate in the **app context**, which means:

| Capability | Supported |
|---|---|
| Read public tweets, timelines, and search | ✅ Yes |
| Read public user profiles | ✅ Yes |
| Access rate limits at the app level | ✅ Yes |
| Post or delete tweets | ❌ No |
| Read or send direct messages | ❌ No |
| Access private or protected account data | ❌ No |
| Follow, like, retweet, or block on behalf of a user | ❌ No |

If you need any write operations or access to private user data, use [OAuth 2.0 PKCE](/authentication/oauth2) instead.

## Get Your Bearer Token from the Developer Portal

Your Bearer Token is available in the [X Developer Portal](https://developer.x.com/en/portal/dashboard) as soon as you create an app.

<Steps>
  <Step title="Open your project in the Developer Portal">
  Go to [developer.x.com](https://developer.x.com/en/portal/dashboard) and sign in. Select the project that contains your app.
  </Step>

  <Step title="Navigate to Keys and Tokens">
  Select your app, then click the **Keys and Tokens** tab. You will see a section labelled **Bearer Token**.
  </Step>

  <Step title="Copy or regenerate your Bearer Token">
  Click **Copy** to copy the existing token, or **Regenerate** to create a new one. If you regenerate the token, the old one is immediately invalidated — update all services that use it before regenerating.
  </Step>
</Steps>

<Warning>
  Your Bearer Token provides direct, unauthenticated access to the X API under your app's identity and rate limits. **Never hardcode it in frontend JavaScript, mobile app binaries, or any code that could be inspected by end users.** Always load it from an environment variable or secrets manager on the server side. If your token is ever exposed, regenerate it immediately in the Developer Portal.
</Warning>

## Using the Bearer Token

Include the Bearer Token in the `Authorization` header of every API request using the `Bearer` scheme.

```
Authorization: Bearer YOUR_BEARER_TOKEN
```

### Examples

<Tabs>
  <Tab title="curl">
    ```bash
    # Search for recent tweets
    curl "https://api.twitter.com/2/tweets/search/recent?query=from%3Axdevelopers&tweet.fields=created_at,author_id" \
      -H "Authorization: Bearer YOUR_BEARER_TOKEN"
    ```

    ```bash
    # Look up a user by username
    curl "https://api.twitter.com/2/users/by/username/XDevelopers?user.fields=name,description,public_metrics" \
      -H "Authorization: Bearer YOUR_BEARER_TOKEN"
    ```
  </Tab>
  <Tab title="Python">
    ```python
    import os
    import requests

    # Load the token from an environment variable — never hardcode it
    bearer_token = os.environ["X_BEARER_TOKEN"]

    headers = {"Authorization": f"Bearer {bearer_token}"}

    # Search for recent tweets
    response = requests.get(
        "https://api.twitter.com/2/tweets/search/recent",
        headers=headers,
        params={
            "query": "from:XDevelopers",
            "tweet.fields": "created_at,author_id,text",
            "max_results": 10,
        },
    )

    response.raise_for_status()
    tweets = response.json()

    for tweet in tweets.get("data", []):
        print(f"[{tweet['created_at']}] {tweet['text']}")
    ```

    ```python
    # Using tweepy's App-Only (Bearer Token) client
    import os
    import tweepy

    client = tweepy.Client(bearer_token=os.environ["X_BEARER_TOKEN"])

    # Fetch a user's public timeline
    user = client.get_user(username="XDevelopers")
    tweets = client.get_users_tweets(id=user.data.id, max_results=5)

    for tweet in tweets.data:
        print(tweet.text)
    ```

    // Load the token from an environment variable — never hardcode it

## Generate a Bearer Token Programmatically

If you prefer to generate a Bearer Token at runtime rather than copying it from the portal, you can request one using your **API Key** (Consumer Key) and **API Key Secret** (Consumer Secret) via the `client_credentials` grant type.

<Note>
  This is an alternative to the portal-based approach, not a replacement. The token returned is functionally identical to the one shown in the Developer Portal. The programmatic approach is useful in automated deployment pipelines where you want to avoid storing long-lived secrets.
</Note>

<CodeGroup>
  ```python Python
  import os
  import base64
  import requests

  api_key = os.environ["X_API_KEY"]
  api_key_secret = os.environ["X_API_KEY_SECRET"]

  # Base64-encode "api_key:api_key_secret"
  credentials = base64.b64encode(f"{api_key}:{api_key_secret}".encode("utf-8")).decode("utf-8")

  response = requests.post(
      "https://api.twitter.com/oauth2/token",
      headers={
          "Authorization": f"Basic {credentials}",
          "Content-Type": "application/x-www-form-urlencoded;charset=UTF-8",
      },
      data={"grant_type": "client_credentials"},
  )

  response.raise_for_status()
  bearer_token = response.json()["access_token"]

  print(f"Bearer token: {bearer_token}")
  ```

  ```javascript JavaScript
  import fetch from "node-fetch";

  const apiKey = process.env.X_API_KEY;
  const apiKeySecret = process.env.X_API_KEY_SECRET;

  // Base64-encode "apiKey:apiKeySecret"
  const credentials = Buffer.from(`${apiKey}:${apiKeySecret}`).toString("base64");

  const response = await fetch("https://api.twitter.com/oauth2/token", {
    method: "POST",
    headers: {
      Authorization: `Basic ${credentials}`,
      "Content-Type": "application/x-www-form-urlencoded;charset=UTF-8",
    },
    body: "grant_type=client_credentials",
  });

  if (!response.ok) {
    throw new Error(`Failed to generate token: ${response.statusText}`);
  }

  const { access_token: bearerToken } = await response.json();
  console.log("Bearer token:", bearerToken);
  ```

  ```bash curl
  # Base64-encode your "API_KEY:API_KEY_SECRET" before running this command
  CREDENTIALS=$(echo -n "YOUR_API_KEY:YOUR_API_KEY_SECRET" | base64)

  curl -X POST "https://api.twitter.com/oauth2/token" \
    -H "Authorization: Basic ${CREDENTIALS}" \
    -H "Content-Type: application/x-www-form-urlencoded;charset=UTF-8" \
    --data "grant_type=client_credentials"
  ```
</CodeGroup>

The response contains the Bearer Token in the `access_token` field:

```json
{
  "token_type": "bearer",
  "access_token": "AAAAAAAAAAAAAAAAAAA..."
}
```

To revoke a programmatically generated Bearer Token, send a `POST` request to `https://api.twitter.com/oauth2/invalidate_token` with the same Basic Auth credentials and the token as the `access_token` body parameter.
